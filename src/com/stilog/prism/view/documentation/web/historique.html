Onglet « Historique »

L'onglet Historique permet d'explorer l'intégralité des modifications enregistrées dans un fichier .vps — qui conserve automatiquement toute l'activité : création, modification et suppression de ressources, d'événements et d'éléments de configuration.

💡 Note : L'onglet Historique est uniquement disponible pour les fichiers .vps. Les fichiers .vpi ne contiennent pas de données historiques.

Chargement

Au chargement d'un fichier VPS, l'historique est traité en arrière-plan en plusieurs étapes :

  1. Extraction des fichiers history.txt et historytracker.txt
  2. Résolution des noms lisibles depuis le VPS (dimensions, événements, arbres de création)
  3. Lecture de history.txt — chaque ligne représente une modification
  4. Indexation en streaming de historytracker.txt — le détail des propriétés modifiées est chargé à la demande au clic, sans jamais tout charger en mémoire

Cette approche permet de gérer des fichiers historytracker.txt de plusieurs gigaoctets sans impact sur les performances.

Filtres communs

La barre de filtres en haut s'applique à tous les sous-onglets simultanément :

  • Recherche globale — filtre par nom, type, utilisateur ou identifiant
  • Modifié par — filtre sur l'utilisateur ayant effectué la dernière modification
  • Créé par — filtre sur l'utilisateur ayant créé l'entrée
  • Modifié / Créé — filtres de date avec les opérateurs : le, après le, avant le, cette semaine, ce mois, cette année
  • Afficher supprimés — par défaut, les entrées dont l'entité n'existe plus dans le VPS sont masquées ; cochez cette option pour les afficher (elles apparaissent en italique grisé)
✅ Astuce : Le bouton ↺ Tout réinitialiser remet à zéro tous les filtres communs et spécifiques en une seule action.

Sous-onglets

Dimensions

Affiche l'historique des ressources (EventResourceX). Le nom de chaque ressource est résolu depuis le VPS : les rubriques d'identification du modèle de dimension sont utilisées pour afficher un label lisible (ex. 5200, M6-1.00 X 25mm LG BHCS au lieu d'un identifiant technique). Le type affiché est le nom de la dimension (ex. OUTSOURCE, NETWORK ACTIVITIES) plutôt que le nom de table interne.

Filtres spécifiques :

  • Dimension — filtre par nom de dimension
  • ☑ Afficher supprimées — identique au filtre global (synchronisé)

Événements

Affiche l'historique des PlanningEvent. Chaque événement est identifié automatiquement par son arbre de création (défini dans eventtreestruct.txt) grâce à la règle : toutes les dimensions obligatoires de l'arbre doivent être renseignées sur l'événement, et l'événement ne doit comporter aucune dimension étrangère à cet arbre.

Le label affiché correspond aux dimensions-clés de l'arbre identifié (ex. NETWORK-EST | Activity 26 | WBS-123).

Filtres spécifiques :

  • Type d'arbre — filtre par arbre de création (ex. 05. Work Order Activity)
  • Date event — filtre sur les dates de début/fin de l'événement : commence après le, commence avant le, finit après le, finit avant le, actif le, cette semaine, ce mois

Autres

Regroupe les modifications de configuration : exports, imports, filtres VP, formulaires, modèles d'éditeur, etc.

Filtre spécifique :

  • Type — filtre par type d'élément de configuration

Panneau de détail

Cliquez sur une ligne dans n'importe quel sous-onglet pour afficher le détail des modifications dans le panneau du bas. Chaque modification est groupée par date et utilisateur — une ligne d'en-tête (fond légèrement coloré) sépare les groupes de modifications simultanées (batch, imports automatiques…).

Le tableau détaille pour chaque modification :

  • # — numéro de la modification dans la séquence
  • Date — horodatage de la modification
  • Utilisateur — auteur de la modification
  • Propriété — nom du champ modifié
  • Ancienne valeur — valeur avant modification
  • Nouvelle valeur — valeur après modification
💡 Performance : Le contenu du panneau de détail est chargé à la demande uniquement au moment du clic — il n'est jamais pré-chargé en mémoire pour l'ensemble de l'historique.
⚠ Attention : Si aucune modification détaillée n'apparaît pour une entrée, c'est que cette entrée n'a pas de données dans historytracker.txt — ce qui est normal pour certains types de modifications (créations initiales, imports batch…).
